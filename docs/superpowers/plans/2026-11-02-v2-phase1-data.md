# V2 Phase 1 — Essential-data completeness (+ U2 spike, U3 ingestion, P2 follow-ups): Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Execute your own task only. Steps use checkbox
> (`- [ ]`) syntax. Write progress to your report file as you go (status, done, in progress, blockers).

**Goal:** Every track in a set shows BPM, key, energy and danceability, or is visibly marked "incomplete" with a reason,
is excluded from scoring, and resolves within 60s or states why it can't.

**Architecture:** The resolver keeps its adapter chain but gains (a) a full local analysis of the 30s Deezer preview
(key via chroma + key profiles, energy and danceability via calibrated loudness/onset/pulse features), (b) a persistent
metadata cache keyed by `trackKeyOf` so a track resolves once, ever, and (c) a background re-resolve queue for
retryable failures. A pure `completenessOf(track)` decides `complete | incomplete(reason)`; the client adds
`resolving` while a request is in flight. The engine skips incomplete tracks; the UI badges and quarantines them and
offers a manual override editor and Mixed In Key CSV import. A U2 data-yield bench measures every source first and
the energy-source decision is made on its numbers.

**Tech Stack:** TypeScript, Next.js 16 route handlers, React 19, Vitest. Existing `mpg123-decoder` + `music-tempo`.

**Spec:** `docs/specs/2026-11-01-v2-product-plan.md` (Phase 0 U2/U3, Phase 1, "working website" criterion 1,
uncertainties 2, 3, 5).

- Never `git add -A`; stage named files; retry on index.lock. Commit author must be
  `Goldilocks111@users.noreply.github.com`. Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Never print `.env` lines; check secrets only via `node --env-file=.env` printing presence/length.

## Review Focus

1. A track that is only missing danceability (common: MIK import, GetSongBPM) must be `incomplete`, not complete,
   and must not be scored — Task 4 test `missing danceability alone is incomplete`.
2. Every set track incomplete (cold cache, providers down) → suggestions fall back to "arc start" logic rather than
   throwing or showing an empty panel with no explanation — Task 5 test `all-incomplete playlist`.
3. Manual override beats every provider, survives a re-resolve and a cache reload — Task 6 test
   `manual override wins over later resolve`.
4. MIK CSV with musical keys ("F#m", "A minor", "Bbmaj") and BOM/semicolon delimiters parses to Camelot —
   Task 7 tests.
5. A preview that is silent, < 5 s, or > 2 MB yields `incomplete('analysis-failed')`, never a garbage key/energy —
   Task 2 test `rejects silence and short audio`.
